# 告警引擎

告警在服务端计算。设备通过 MQTT 或 HTTP 上报后，统一事件进入 `TwinHub`，告警引擎按 `payload` 字段评估规则；离线规则由定时扫描评估。告警事件保存在 `data/alerts.sqlite3`，与遥测时序库分离。触发、恢复、确认均通过 `/ws/twin` 的独立 `type: "alert"` 信封推送。

这里的告警针对设备状态与业务阈值。Broker 连接失败目前只写服务端警告日志并反映在 `/api/v1/health`，没有单独生成“Broker 断线”业务告警；已上报设备随后停报时，离线规则仍可触发设备离线告警。排查方式见 [MQTT 故障提示](MQTT_INTEGRATION.md#broker-故障提示与告警边界)。

## 规则

编辑 `server/assets/alert-rules.json` 后重启服务生效。每条规则包含：

| 字段 | 含义 |
| --- | --- |
| `id`、`name` | 唯一规则标识、显示名称 |
| `twinId` | 设备 ID；`*` 匹配全部已上报设备 |
| `field` | `payload` 中的数值字段；`@offline` 表示设备停止上报 |
| `op`、`threshold` | `lt/lte/gt/gte/eq/ne` 与数值阈值；离线规则的阈值单位为秒 |
| `for` | 字段条件持续满足的秒数；每次收到相应字段时检查，条件中断会重新计时 |
| `level`、`message` | `critical/warning/info`；消息支持 `{value}`、`{threshold}`、`{twinId}`、`{name}` |

离线规则只跟踪服务启动后已收到消息的设备，避免把尚未接入的静态设备误判离线。设备重新上报时自动恢复离线告警。字段回到正常范围时自动恢复字段告警。一个规则和设备组合同时只保留一条活动告警；服务重启会从数据库恢复活动告警。

当前规则包含会议室湿度、空调温度、电量与设备离线。默认演示适配器会周期上报会议室湿度，能看到湿度告警触发与恢复。演示数据不代表真实运行状态。

## 接口与页面

- `GET /api/v1/alerts?active=1`：未恢复告警。
- `GET /api/v1/alerts?limit=100&twinId=...&level=...&since=...`：历史记录与活动列表。
- `GET /api/v1/alerts/rules`：当前规则和引擎状态。
- `GET /api/v1/alerts/stats?since=...`：按级别、设备、规则统计。
- `POST /api/v1/alerts/{id}/ack`：确认已查看；不改变触发与恢复状态。

列表、规则、统计和确认无需登录。页面“告警中心”提供进行中、历史和报表三个页签。告警数量、设备状态和 3D 黄色标记均依据活动告警更新；场景中的“告警”图层开关只控制 3D 告警标记。

当前实现按单个 FastAPI 进程运行扫描器。多进程部署前需要把设备最后上报时间与扫描器协调到共享服务；规则更新目前通过修改 JSON 并重启服务完成。
